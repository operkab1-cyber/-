## 1. Кто пользуется админкой и что видит

Одна и та же оболочка CMS обслуживает два уровня доступа:

| Роль | Что видит | Ограничения |
|---|---|---|
| **Поставщик** (владелец каталога) | Только свои растения, свои заказы, свою аналитику | Не видит чужие каталоги, цены и остатки конкурентов |
| **Сотрудник поставщика** (если компания добавит несколько пользователей) | То же, что владелец, кроме биллинга и приглашения новых сотрудников | Настраивается через роль внутри `users.company_id` |
| **Администратор платформы** | Все каталоги в режиме read + возможность точечно вмешаться (заблокировать позицию, поправить категорию) | Не редактирует цены/остатки чужого каталога напрямую — только модерирует |

Ниже все шаги описаны с точки зрения **Поставщика** — это основной пользователь CMS изо дня в день.

## 2. Дашборд — стартовый экран

При входе в раздел «Каталог» поставщик видит не пустую таблицу, а сводку — это тот же дашборд из UX Bible (Этап 2, раздел 5.1), здесь расписан подробнее применительно к CMS:

```
┌─────────────────────────────────────────────────────────────┐
│  165 товаров · 2 нет в наличии · 3 требуют внимания AI ⚠      │
├─────────────────────────────────────────────────────────────┤
│  [+ Добавить растение]  [⇧ Импорт из Excel]  [Обновить остатки]│
├─────────────────────────────────────────────────────────────┤
│  Таблица каталога:                                            │
│  Фото │ Название │ Категория │ Остаток │ Цена от │ Статус │ ⋮  │
└─────────────────────────────────────────────────────────────┘
```

«3 требуют внимания AI» — это счётчик карточек, где AI-описание (Этап 6, раздел 6) сгенерировано, но ещё не подтверждено поставщиком, или где AI-проверка фото (Этап 6, раздел 7) нашла несоответствие. Это первое, что видит поставщик — не нужно искать проблемные карточки вручную.

## 3. Как ты добавляешь растение

### 3.1 Ручное добавление — с нуля

1. Нажимаешь **«+ Добавить растение»** на дашборде каталога.
2. Открывается пошаговая форма (прогресс-степпер, как в онбординге, Этап 2, раздел 4.2):
   - **Шаг 1 — Основное:** название (ru), категория (дерево с автодополнением — начинаешь печатать «хвой…», система сама предлагает «Хвойные → Туи»), латинское название (необязательно на этом шаге).
   - **Шаг 2 — Фото:** загрузка (см. раздел 6).
   - **Шаг 3 — Характеристики:** форма меняется в зависимости от выбранной категории — для «Туи» появятся поля «зона морозостойкости», «объём контейнера», «высота»; для «Грунтов» — «объём упаковки, л», «состав» (динамические поля из `attributes`, Этап 5).
   - **Шаг 4 — Цена и остаток:** минимум одна ступень цены (раздел 4) и текущий остаток (раздел 5).
3. Кнопка **«Сохранить как черновик»** доступна на любом шаге — ничего не теряется, если отвлёкся.
4. На финальном шаге — **«Сгенерировать описание с AI»** (по желанию, необязательный шаг) — вызывает пайплайн из Этапа 6 (раздел 6): AI пишет 2–3 предложения на основе уже введённых характеристик, ты видишь черновик текста и можешь отредактировать перед сохранением.
5. **«Опубликовать»** — товар получает статус `active` и появляется в публичном каталоге (Этап 4, ISR-ревалидация подхватывает карточку в течение 1–2 минут).

### 3.2 Добавление через дублирование

Для похожего товара (например, тот же вид, другой сорт) — на существующей карточке кнопка **«Дублировать»** копирует все поля кроме фото и остатка, открывая форму на Шаге 1 с предзаполненными данными. Это быстрее, чем заполнять с нуля для питомника с десятками сортов одного вида (в вашем прайсе — например, 12 позиций одного только барбариса Тунберга).

### 3.3 Массовое добавление

Для больше одного товара за раз — не через эту форму, а через импорт Excel (раздел 7), который для новых поставщиков обычно и есть основной способ первого наполнения каталога.

## 4. Как ты меняешь цены

### 4.1 Точечное изменение (одна позиция)

На карточке товара в CMS — блок «Цены» с таблицей ступеней:

```
Мин. кол-во │ Цена │ Валюта
────────────┼──────┼────────
1 шт        │ 1200 │ EUR      [✎] [🗑]
50 шт       │ 1050 │ EUR      [✎] [🗑]
            [+ Добавить ступень]
```

Клик по [✎] делает строку редактируемой инлайн (без перехода на отдельный экран), сохранение — по Enter/blur, с мгновенным тостом-подтверждением («Цена обновлена»). Изменение сразу видно покупателям, стоящим на странице товара, через Realtime-канал (Этап 4, раздел 6.4) — цена не «протухает» в чужой открытой вкладке.

### 4.2 Массовое изменение цен

Для сценария «повысить все цены на 5% из-за роста себестоимости» — отдельный экран **«Массовое изменение цен»**:
1. Выбираешь товары чекбоксами в таблице каталога (или всю категорию целиком, или весь каталог).
2. Задаёшь правило: `+ 5%`, `− 200 ₽`, или `установить фиксированную цену X` — на выбор.
3. Экран показывает **предпросмотр** («до / после») по первым 10 позициям, прежде чем применить ко всем — так же, как предпросмотр импорта Excel (раздел 7), чтобы не применить ошибочное правило вслепую.
4. Кнопка «Применить к N товарам» — действие логируется (раздел 9) с возможностью отменить одним кликом в течение 24 часов («откат» хранит предыдущие значения `prices` во временной таблице `price_change_log`).

### 4.3 Сезонные/промо-цены

Поле `valid_from`/`valid_to` (Этап 5, таблица `prices`) доступно как опция «Ограничить сроком действия» при добавлении ступени — удобно для сезонных скидок на, например, посадочный материал перед началом сезона.

## 5. Как ты обновляешь остатки

### 5.1 На desktop — из таблицы каталога

Колонка «Остаток» в таблице каталога — редактируется инлайн прямо в списке, без открытия карточки: клик по числу → поле становится редактируемым → Enter сохраняет. Для 165 позиций это значит, что после физической инвентаризации можно пройтись по всей таблице за несколько минут, не открывая каждую карточку отдельно.

### 5.2 На мобильном — «в поле»

Как зафиксировано в UX Bible (Этап 2, раздел 5.2) — на территории питомника открываешь мобильное приложение, находишь товар (поиском или сканированием, если есть QR-бирка), и свайпом по строке открывается компактный степпер `[-] 42 [+]` для быстрой корректировки без набора текста. Изменения кешируются локально и синхронизируются, когда появляется связь (офлайн-режим, Этап 4, раздел 14.2) — актуально, если на территории питомника плохое покрытие сети.

### 5.3 Автоматические оповещения

- Остаток пересекает порог «мало» (настраиваемый, по умолчанию < 10% от типичного объёма) → бейдж «Мало осталось» на карточке автоматически, без твоего участия.
- Остаток становится 0 → статус карточки автоматически меняется на «нет в наличии», кнопка «В корзину» у покупателей заменяется на «Сообщить о поступлении» (Этап 7, раздел 2) — все, кто оставил заявку на этот товар, получат уведомление, как только ты снова укажешь остаток больше нуля.

### 5.4 Массовое обновление остатков

Тот же экран, что и массовое изменение цен (раздел 4.2), с переключателем «Цены / Остатки» — логика предпросмотра и логирования идентична.

## 6. Как ты загружаешь фото

### 6.1 Загрузка на карточке товара

- Зона drag-and-drop (или клик для выбора файла) — до 8 фото на товар, первое становится обложкой автоматически (можно переназначить перетаскиванием).
- Пока идёт загрузка — плейсхолдер с прогресс-баром на месте будущего фото (не блокирует заполнение остальной формы).
- Сразу после загрузки — фото проходит **AI-проверку** (Этап 6, раздел 7): 2–5 секунд, результат появляется прямо на миниатюре:
  - ✅ зелёная галочка — вид на фото соответствует названию карточки, качество достаточное
  - ⚠ жёлтый предупреждающий бейдж — например, «Похоже на другой сорт можжевельника — проверьте» или «Низкое разрешение» — карточку всё ещё можно опубликовать, но с предупреждением в общем счётчике на дашборде (раздел 2)
  - Ты можешь загрузить другое фото или подтвердить текущее, если предупреждение ложное (обратная связь идёт в лог для улучшения модели, Этап 6, раздел 13.4)

### 6.2 Требования к фото (подсказка прямо в интерфейсе)

Минимальное разрешение, соотношение сторон для обложки, рекомендация показать растение целиком + крупный план листвы/цветка — короткая памятка рядом с зоной загрузки, а не отдельная страница документации.

### 6.3 Массовая загрузка фото при импорте Excel

Если у тебя уже есть папка с фото, названными по артикулу/названию товара — при импорте Excel (раздел 7) можно на отдельном шаге загрузить архивом всю папку сразу, система сопоставит файлы с товарами по имени файла или по колонке «Артикул фото», если она есть в исходной таблице.

## 7. Как ты импортируешь Excel

Это самый важный флоу CMS — большинство поставщиков впервые заполняют каталог именно так, а не через ручную форму. Разберём на вашем реальном файле.

### 7.1 Шаг 1 — Загрузка файла

Загружаешь `.xlsx`/`.csv` в зону импорта. Система читает первый лист и показывает **предпросмотр первых 10 строк как есть**, без изменений — чтобы ты сразу видел, что именно она прочитала.

### 7.2 Шаг 2 — Сопоставление колонок

Для вашего файла система автоматически распознает:

```
Колонка в файле        →  Поле в каталоге
─────────────────────────────────────────
"НАЗВАНИЕ"              →  Сырое название (будет разобрано AI)
"Цена"                  →  Цена, ступень "от 1 шт"
"Unnamed: 2"             →  ⚠ не распознано автоматически —
                            система заметила, что в этой колонке
                            встречается текст "нет в наличии" у 2 строк
                            → предлагает: "Использовать как отметку
                            «нет в наличии»?"  [Да] [Пропустить колонку]
```

Ты подтверждаешь или поправляешь сопоставление вручную (выпадающий список у каждой колонки файла: «Название» / «Цена» / «Остаток» / «Категория» / «Игнорировать»). Сопоставление запоминается для этого поставщика — при следующей загрузке обновлённого прайса (как у вас в имени файла — «с 25.06.2026», предполагающего, что это не первая версия) система предложит то же сопоставление автоматически.

### 7.3 Шаг 3 — AI-разбор и предпросмотр

Для каждой строки запускается пайплайн AI-описаний (Этап 6, раздел 6). Экран показывает таблицу **«было / стало»**, отсортированную так, что строки с низкой уверенностью AI — сверху, а не в общем потоке:

| Было (исходная строка) | Стало (структурировано) | Уверенность |
|---|---|---|
| `Бересклет Форчуна Эмеральд Гэити Co5Pa ШТАМБ 60-120 (Euonymus fortunei Emerald Gaiety)` | Категория: Бересклет · Латынь: *Euonymus fortunei* 'Emerald Gaiety' · Контейнер: 5л · Форма: штамб · Высота: 60–120см | ✅ высокая |
| `Клён пальчатый Катсура Со2` | Категория: Клёны · Латынь: *Acer palmatum* 'Katsura' · Контейнер: 2л | ⚠ средняя — латынь предположена по названию сорта, не указана в файле |
| `Барбарис Тунберга Со2-3` | Категория: Барбарис · Контейнер: 2–3л · Сорт: не определён (базовый вид) | ⚠ средняя — «Co2-3» истолковано как диапазон объёма контейнера, проверьте |

Строки с ⚠ выделены и кликабельны — открываешь, поправляешь одним полем прямо в этой таблице, не уходя на отдельный экран.

### 7.4 Шаг 4 — Категоризация

Система группирует товары по категориям автоматически (в вашем случае предложит: Можжевельники — 32, Туи — 21, Барбарис — 12 и т.д., используя ту же логику, что показана в Этапе 6). Категории, которых ещё нет в дереве `categories`, помечены «Новая категория — создать?» — подтверждаешь одним кликом на группу, а не на каждый товар.

### 7.5 Шаг 5 — Финальное подтверждение

- Сводка: «163 товара будут созданы как черновики, 2 — со статусом «нет в наличии», обнаружено 5 позиций с низкой уверенностью AI — требуют вашей проверки перед публикацией».
- Кнопка **«Импортировать»** — все товары попадают в каталог со статусом `draft`, **не публикуются автоматически** (тот же принцип human-in-the-loop, что в Этапе 6) — ты просматриваешь и публикуешь пакетно или по одному из общего списка черновиков.
- Позиции с низкой уверенностью попадают в тот же счётчик «требуют внимания AI» на дашборде (раздел 2).

### 7.6 Повторный импорт (обновление прайса)

Если ты загружаешь новую версию файла (как в вашем случае — прайс от 25.06 поверх более раннего), система сопоставляет строки с уже существующими товарами по названию + латыни (fuzzy match), а не создаёт дубликаты — предлагает: «144 совпадения найдены — обновить цену/остаток; 12 новых позиций — создать; 3 позиции из старого файла отсутствуют в новом — пометить как «нет в наличии»?».

## 8. Как ты смотришь аналитику

Раздел «Аналитика» (UX Bible, Этап 2, раздел 5.4) в CMS-контексте — это не абстрактные графики, а конкретные ответы на вопросы, которые задаёт себе поставщик:

### 8.1 Дашборд аналитики

```
┌───────────────────────────────────────────────────────┐
│  Продажи за период  [Неделя ▾]  [Месяц]  [Сезон]        │
│  ▁▂▃▅▇▆▄▂▁  График выручки/заказов                       │
├───────────────────────────────────────────────────────┤
│  Топ-5 товаров по спросу       │  Спрос по регионам      │
│  1. Туя Смарагд        42 шт   │  ▓▓▓▓▓ Германия          │
│  2. Можжевельник Блю Э. 31 шт   │  ▓▓▓ Польша              │
│  ...                            │  ▓▓ Нидерланды           │
├───────────────────────────────────────────────────────┤
│  Товары без просмотров за 30 дней (требуют внимания)     │
│  → возможно, нужно фото/описание/цена конкурентнее        │
├───────────────────────────────────────────────────────┤
│  Сравнение цены со средней по рынку (анонимизировано)     │
└───────────────────────────────────────────────────────┘
```

### 8.2 Что можно посмотреть детальнее

| Вопрос | Где ответ |
|---|---|
| «Сколько я заработал за месяц?» | Виджет «Продажи за период» + экспорт в PDF/CSV для бухгалтерии |
| «Какой товар продаётся лучше всего?» | «Топ-5 по спросу», кликабельно — ведёт к карточке товара |
| «В каких странах спрос растёт?» | Тепловая карта регионов (данные из `orders.shipping_address`) |
| «Почему товар не продаётся?» | Блок «Без просмотров» — часто причина в отсутствующем фото или AI-описании, не подтверждённом вручную (перелинковка на карточку с открытым разделом характеристик) |
| «Моя цена рыночная?» | Анонимизированное сравнение со средней ценой по категории у других поставщиков платформы — без раскрытия, с кем именно сравнивается |
| «Сколько заявок (`requests`) я не обработал вовремя?» | Отдельный виджет с дедлайнами SLA (Этап 7, раздел 11.2) |

### 8.3 Экспорт

Любой график/таблица аналитики — кнопка «Экспорт» (CSV для собственных расчётов, PDF для отчёта — тот же механизм экспорта, что и в Этапе 7, раздел 10).

## 9. Права доступа и журнал действий

- Все изменения цен, остатков, массовые операции (разделы 4.2, 5.4) и импорты (раздел 7) фиксируются в `audit_log(actor_id, action, entity_type, entity_id, before, after, created_at)` — новая служебная таблица, расширяющая принцип аудита из Архитектуры (Этап 4, раздел 12.3).
- Владелец компании может пригласить сотрудников с ограниченной ролью (например, «только обновление остатков», без доступа к ценам и биллингу) — гибкость на будущее, не обязательно для MVP (см. приоритизацию ниже).
- Администратор платформы видит агрегированный журнал массовых операций по всем поставщикам — не содержимое (это приватные коммерческие данные), а факт и масштаб операции («Поставщик X изменил цены на 340 товаров, 09.07.2026 14:32») — для обнаружения аномалий (Этап 6, раздел 9) без вторжения в чужие данные.
