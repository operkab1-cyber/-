## 1. Принципы UX и информационная архитектура

### 1.1 Принципы дизайна

1. **Прозрачность прежде всего.** Цена, наличие, сроки и статус верификации видны без дополнительных кликов — это ключевое конкурентное отличие Tamga Green (см. PRD, раздел 10).
2. **Профессиональная скорость.** Пользователи B2B (закупщики питомников, менеджеры садовых центров) ценят время — минимум кликов от поиска до заявки, никаких лишних модальных окон.
3. **Доверие через данные.** Каждый элемент, связанный с поставщиком (рейтинг, сертификаты, история сделок), должен быть виден в момент принятия решения, а не спрятан на отдельной вкладке.
4. **Один каркас — четыре роли.** Общая навигационная логика и визуальный язык для Поставщика, Покупателя, Администратора и (позже) Потребителя, чтобы снизить стоимость разработки и обучения.
5. **Живой товар требует живых данных.** Остатки, сроки доставки и сезонная доступность растений должны обновляться в реальном времени и явно отображать «протухание» данных (например, «остаток обновлён 2 часа назад»).

## 2. Сквозные состояния интерфейса

Эти паттерны применяются на всех экранах платформы, поэтому описаны один раз и переиспользуются.

### 2.1 Пустые состояния (Empty States)

| Экран | Когда возникает | Что показываем |
|---|---|---|
| Каталог поставщика | Товаров ещё не добавлено | Иллюстрация + текст «Добавьте первый товар, чтобы покупатели вас нашли» + кнопка «Добавить товар» |
| Результаты поиска | Ничего не найдено по фильтрам | «По вашему запросу ничего не найдено» + кнопка «Сбросить фильтры» + блок «Похожие товары» |
| Заказы (покупатель) | Заказов ещё не было | «Вы ещё не сделали ни одного заказа» + кнопка «Перейти в каталог» |
| Сообщения | Нет переписок | «Начните диалог с поставщиком со страницы товара» |
| Избранное | Пусто | «Сохраняйте понравившихся поставщиков и товары, нажимая ★ на карточке» |
| Корзина заявок | Пусто | «Корзина пуста» + кнопка «Перейти в каталог» + (для вернувшихся) «Ваши недавно просмотренные товары» |
| Аналитика (новый поставщик) | Недостаточно данных за период | «Аналитика появится после первых 5 заказов» + прогресс-бар «3 из 5» |
| Очередь верификации (админ) | Все заявки обработаны | «Новых заявок нет» + ссылка на архив обработанных |

### 2.2 Ошибки

| Тип ошибки | Где происходит | Поведение UI |
|---|---|---|
| Валидация формы | Регистрация, добавление товара, чекаут | Инлайн-подсветка поля красным + текст ошибки под полем, фокус авто-переходит на первое невалидное поле |
| Ошибка загрузки данных (5xx/сеть) | Любой экран со списком/дашбордом | Баннер «Не удалось загрузить данные» + кнопка «Повторить», скелетон-заглушки не сбрасываются резко |
| Товар закончился между просмотром и оформлением | Корзина/чекаут | Строка товара помечается жёлтым, текст «Остаток изменился: доступно 12 из 20», кнопка «Обновить количество» |
| Ошибка оплаты | Чекаут | Модальное окно с причиной (по возможности из платёжного шлюза), кнопка «Повторить оплату» / «Выбрать другой способ», заказ сохраняется как «Ожидает оплаты» |
| Истёк срок действия сессии | Любой защищённый экран | Мягкий редирект на логин с сохранением текущего состояния формы (draft в localStorage) и текстом «Сессия истекла, войдите снова» |
| Отказ в верификации | Онбординг поставщика/покупателя | Экран статуса с конкретной причиной отказа и кнопкой «Загрузить документы повторно», доступен чат с поддержкой |
| Конфликт мультивендорной корзины (разные условия доставки) | Корзина | Некритичное предупреждение: «Заказ будет разбит на 2 отправки от разных поставщиков» с разбивкой по посылкам |

### 2.3 Состояния загрузки

- **Скелетоны** (skeleton screens) — для каталога, карточек товара, дашбордов — вместо спиннеров, чтобы сохранить ощущение структуры страницы.
- **Оптимистичный UI** — для действий вроде «добавить в избранное» или «добавить в корзину»: элемент обновляется мгновенно, откатывается при ошибке сервера.
- **Прогресс верификации документов** — линейный прогресс-бар с шагами (Загружено → На проверке → Подтверждено), а не бинарный спиннер.

## 3. Публичная зона (до регистрации)

### 3.1 Главная страница

**Назначение:** объяснить ценность платформы за 5 секунд и провести к регистрации нужной роли.

**Структура (desktop):**
- Шапка: логотип, «Как это работает», «Тарифы», «Каталог», кнопки «Войти» / «Регистрация» (primary CTA)
- Hero-блок: заголовок с ключевым УТП («Все питомники Европы — в одном окне»), переключатель «Я поставщик» / «Я покупатель», меняющий CTA и подзаголовок под сегмент
- Блок логотипов/цифр доверия (число поставщиков, стран, товаров — динамически из аналитики платформы)
- Блок «Как это работает» — 3 шага для каждой роли (табы)
- Блок с превью каталога (живые карточки товаров с реальными остатками — для демонстрации прозрачности)
- Отзывы/кейсы
- Футер: юридическая информация, контакты, ссылки на блог/базу знаний

**Кнопки и переходы:**
- «Регистрация» → экран выбора роли (4.1)
- «Войти» → форма логина
- Клик по карточке товара в превью → публичная карточка товара (без цены, с CTA «Войдите, чтобы увидеть цену и оформить заявку»)

**Пустое/ошибочное состояние:** если backend аналитики недоступен — статичные плейсхолдер-цифры вместо живых, без ошибки на весь экран.

### 3.2 Публичный каталог (просмотр без входа)

- Доступны: фото, название, категория, страна происхождения, сертификаты.
- Скрыты: точная цена, контакты поставщика, кнопка «В корзину» — заменена на «Войдите, чтобы заказать».
- Цель: SEO-трафик и мягкая конверсия в регистрацию.

## 4. Онбординг и верификация

### 4.1 Выбор роли

Простой экран с двумя крупными карточками: «Я поставщик — продаю растения и товары» / «Я покупатель — закупаю для садового центра/ландшафтных проектов». Выбор определяет весь последующий флоу форм.

### 4.2 Форма регистрации компании

**Поля (общие):** название компании, страна, юридический адрес, ИНН/VAT-номер, email, телефон, пароль, чекбокс согласия с условиями.

**Поля (только Поставщик, доп. шаг):** категории товаров, фитосанитарный сертификат (загрузка файла), сертификаты качества/органик (опционально), фото производства.

**Поля (только Покупатель, доп. шаг):** тип бизнеса (садовый центр / ландшафтная компания / прочее), примерный объём закупок в месяц, регион доставки.

**Валидация:** проверка формата VAT-номера по маске страны в реальном времени; email — проверка на дубликат существующего аккаунта с подсказкой «Возможно, у вас уже есть аккаунт — войти?».

**Кнопки:** «Далее» (переход по шагам, прогресс-индикатор 1/3, 2/3, 3/3), «Назад», на финальном шаге — «Отправить на проверку».

### 4.3 Статус верификации

Экран-ожидание после отправки документов:
- Статус-трекер: Загружено → На проверке (обычно 24–48 часов) → Подтверждено/Отклонено
- Пока не подтверждено: доступен просмотр каталога в режиме read-only, но недоступны заказ/загрузка товаров
- При отклонении — конкретная причина + кнопка «Загрузить документы снова» + чат с поддержкой (см. 2.2)

## 5. Кабинет Поставщика

### 5.1 Дашборд поставщика

**Виджеты:**
- Новые заказы, требующие подтверждения (с таймером — сколько осталось до автоотмены)
- График продаж за период (переключатель: неделя/месяц/сезон)
- Топ-товары по спросу
- Уведомления системы (например, «истекает сертификат через 30 дней»)
- Быстрые действия: «Добавить товар», «Ответить на сообщения», «Обновить остатки»

### 5.2 Управление каталогом

**Вид:** таблица товаров с колонками — фото, название, категория, остаток, цена (опт/мелкий опт), статус (активен/скрыт/закончился), действия.

**Добавление товара — форма:**
- Название, категория (дерево категорий с автодополнением), фото (до 8, drag-n-drop, обязательна минимум 1)
- Характеристики по категории (динамические поля: для растений — зона морозостойкости, высота, диаметр горшка, сезон доступности; для инструментов — материал, размер)
- Цена по объёму (ступенчатая шкала: «1–10 шт — X€, 11–50 шт — Y€»)
- Остаток и единица измерения
- Сертификаты (привязка к загруженным ранее документам компании или новая загрузка)
- Кнопки: «Сохранить черновик», «Опубликовать»

**Массовые операции:** загрузка каталога через CSV/Excel-шаблон (для крупных поставщиков), кнопка «Скачать шаблон», предпросмотр перед импортом с подсветкой ошибок построчно.

**Мобильное отличие:** быстрое обновление остатка через свайп по строке товара (для использования «в поле» на территории питомника, см. UC-15 в PRD) вместо открытия полной формы.

### 5.3 Заказы поставщика

Канбан-подобный список статусов: Новый → Подтверждён → Собран → Отгружен → Доставлен → Завершён / Спор.
Карточка заказа: покупатель, состав, сумма, дедлайн подтверждения, кнопки «Подтвердить» / «Отклонить» (с обязательным указанием причины) / «Изменить срок отгрузки».

### 5.4 Аналитика спроса

Графики: спрос по регионам (карта Европы с тепловой картой), сезонность по категориям, сравнение цены товара со средней по рынку (анонимизировано). Цель — помочь поставщику планировать выращивание (см. UC-04 PRD).

### 5.5 Профиль компании и настройки

Публичная витрина компании (видна покупателям): логотип, описание, сертификаты, рейтинг, отзывы. Отдельно — приватные настройки: реквизиты для выплат, уведомления, тарифный план.

## 6. Кабинет Покупателя (B2B)

### 6.1 Дашборд покупателя

**Виджеты:**
- Активные заказы и их статус доставки (трекинг)
- Рекомендации «Возможно, вам нужно» на основе истории закупок и сезона
- Избранные поставщики с индикатором «есть новые товары»
- Быстрый доступ к калькуляторам

### 6.2 Заказы и история

Список заказов с фильтром по статусу/поставщику/периоду, для каждого — детализация состава, документы (накладные, фитосертификаты) для скачивания, кнопка «Повторить заказ» (создаёт новую корзину с теми же позициями, актуализируя цены и остатки).

### 6.3 Избранное

Две вкладки: «Товары» и «Поставщики». По поставщику — быстрая кнопка «Написать» и «Смотреть весь каталог».

## 7. Маркетплейс: поиск, фильтры, карточка товара

### 7.1 Поиск

- Строка поиска в шапке, доступна на всех экранах кабинета покупателя.
- Автодополнение с категориями и популярными запросами по мере ввода (после 2 символов).
- Поддержка поиска по латинскому/народному названию растения (например, «hydrangea» находит и «гортензия»).
- История последних запросов и «сохранённые поисковые запросы» с опцией подписки на уведомления о новых поступлениях.

### 7.2 Фильтры

Расположены слева (desktop) / в выпадающей панели по кнопке «Фильтры» (mobile/tablet):

| Группа фильтров | Значения |
|---|---|
| Категория | Дерево категорий (растения → деревья/кустарники/многолетники…, инструменты, грунты и т.д.) |
| Регион поставщика | Страна/регион по карте Европы |
| Сертификация | Органик, локальное производство, конкретные фитосертификаты |
| Зона морозостойкости | По стандартной шкале зон |
| Цена | Слайдер диапазона |
| Минимальный объём заказа | Слайдер/чекбоксы |
| Рейтинг поставщика | От 4★ и выше и т.д. |
| Наличие | Только «в наличии сейчас» |

**Поведение:** применённые фильтры отображаются как «чипы» над списком результатов с возможностью удалить по одному; счётчик результатов обновляется живо при каждом изменении (без нажатия «Применить» на desktop; на mobile — с кнопкой «Показать N товаров» в конце панели, чтобы не дёргать список на каждый тап).

### 7.3 Карточка товара

**Элементы:** галерея фото/видео, название, категория, поставщик (с рейтингом и бейджем верификации), цена по объёму (таблица), остаток с датой обновления, характеристики, сертификаты, блок «Доставка и сроки» (с учётом региона покупателя — расчёт через модуль логистики), кнопка «Добавить в корзину» (с выбором количества), кнопка «Написать поставщику», блок «Похожие товары», отзывы о поставщике.

**Мобильная адаптация:** галерея — свайп на всю ширину экрана, sticky-панель внизу с ценой и кнопкой «В корзину», остальной контент — раскрывающиеся аккордеоны (характеристики, доставка, отзывы).

## 8. Корзина заявок и оформление заказа

### 8.1 Корзина заявок

Особенность B2B-маркетплейса: корзина мультивендорная и группируется по поставщикам.

**Структура:**
- Группы товаров по поставщику, с суммой по каждой группе
- Внутри группы: возможность менять количество (с учётом ступенчатых цен — изменение количества live-пересчитывает цену за единицу)
- Индикатор минимального объёма заказа у поставщика, если не достигнут — предупреждение «Добавьте ещё товаров на 45€, чтобы оформить заказ у этого поставщика»
- Итоговая сумма по всей корзине + разбивка по будущим отправкам (см. 2.2 «конфликт мультивендорной корзины»)
- Кнопка «Сохранить как черновик» (для согласования закупки внутри компании покупателя) и «Оформить заказ»

### 8.2 Оформление заказа (чекаут)

Пошаговый процесс:
1. **Адрес и получатель** — выбор из сохранённых адресов объектов (актуально для ландшафтных компаний с разными объектами) или новый адрес
2. **Способ доставки** — расчёт через калькулятор логистики (см. раздел 9), опции: доставка перевозчиком-партнёром / самовывоз с хаба / собственный транспорт покупателя
3. **Способ оплаты** — оплата картой/SEPA, инвойс с отсрочкой (для верифицированных покупателей с кредитным лимитом), эскроу для новых контрагентов
4. **Подтверждение** — итоговый обзор заказа по каждому поставщику отдельно, чекбокс согласия с условиями поставки, кнопка «Подтвердить заказ»

**После оформления:** экран успеха с номерами заказов (отдельный номер на каждого поставщика, если корзина мультивендорная), кнопки «Отследить заказ» и «Скачать инвойс».

## 9. Калькуляторы

Платформа включает три встроенных калькулятора, доступных из кабинета покупателя и из карточки товара:

### 9.1 Калькулятор доставки

Вход: адрес получателя, вес/объём/тип груза (обычная посылка vs. живые растения с температурным режимом). Выход: список опций доставки с ценой и сроком, интеграция с модулем логистики поставщика.

### 9.2 Калькулятор объёма для проекта (для ландшафтных компаний)

Вход: площадь/периметр объекта, тип посадки (например, «живая изгородь», «клумба», «озеленение кровли»), плотность посадки. Выход: рекомендованное количество единиц растений нужной категории с возможностью сразу добавить рассчитанное количество в корзину. Интерфейс — пошаговая форма с визуальной схемой (простая 2D-иллюстрация расположения растений).

### 9.3 Калькулятор экономии при опте

Вход: желаемое количество товара. Выход: сравнение цены при разных объёмах закупки (визуализация ступенчатой шкалы цены поставщика) — помогает покупателю решить, стоит ли увеличить объём заказа для получения скидки.

**Общее поведение калькуляторов:** результат сразу можно перенести в корзину заявок одной кнопкой «Добавить результат в корзину», без необходимости вручную переносить цифры.

## 10. AI-помощник

Доступен как плавающая иконка чата в правом нижнем углу на всех экранах кабинета (desktop) / как отдельный пункт нижней таб-панели (mobile).

### 10.1 Сценарии использования

| Роль | Пример запроса | Ответ AI-помощника |
|---|---|---|
| Покупатель | «Нужны морозостойкие кустарники для живой изгороди в Польше, бюджет до 500€» | Подборка товаров с фильтрами, применёнными автоматически, ссылка «Открыть в каталоге» |
| Покупатель | «Сравни этих двух поставщиков туи» | Таблица сравнения цены/сроков/рейтинга/сертификатов прямо в чате |
| Поставщик | «Почему упал спрос на розы в этом месяце?» | Текстовый инсайт со ссылкой на график в разделе Аналитика |
| Поставщик | «Помоги составить описание для нового товара» | AI предлагает черновик описания на основе загруженных фото и характеристик, с кнопкой «Вставить в форму» |
| Ландшафтная компания | «Рассчитай, сколько саженцев туи нужно для изгороди 40 метров» | AI вызывает калькулятор объёма (раздел 9.2) и показывает результат в чате |
| Любая роль | «Где мой заказ №1234?» | AI подтягивает статус заказа и трек-номер, не заставляя переходить на другой экран |

### 10.2 UI-паттерн

- Окно чата: история сообщений, поле ввода, быстрые кнопки-подсказки под первым открытием («Найти товар», «Рассчитать объём», «Статус заказа»)
- Ответы могут включать не только текст, но и встроенные карточки товаров, таблицы сравнения, мини-графики — не только текстовый ответ
- Кнопка «Передать оператору поддержки», если AI не справляется с запросом (эскалация в раздел Сообщения, 11)
- Индикатор «AI печатает…» и стриминг ответа для ощущения живого диалога

## 11. Сообщения и уведомления

### 11.1 Сообщения

Единый инбокс, объединяющий переписки с контрагентами и эскалации от AI-помощника. Список диалогов слева, окно переписки справа (desktop) / полноэкранный список → полноэкранный диалог (mobile). Возможность прикрепить файл, ссылку на товар/заказ прямо в сообщении (превью-карточка внутри чата).

### 11.2 Уведомления

Колокольчик в шапке с бейджем непрочитанных. Категории: заказы (новый заказ, изменение статуса), сообщения, система (истекает сертификат, изменение тарифа), маркетинг (опционально, с возможностью отключить отдельно). Настройки уведомлений — отдельная страница с чекбоксами по каждой категории и каналу (в приложении / email / push).

## 12. Кабинет Администратора

### 12.1 Очередь верификации

Список заявок на регистрацию поставщиков/покупателей со статусом «Ожидает проверки», карточка заявки с загруженными документами (просмотр PDF/изображений прямо в интерфейсе, без скачивания), кнопки «Подтвердить» / «Отклонить» (с обязательным указанием причины, которая уйдёт пользователю, см. 4.3).

### 12.2 Модерация споров

Карточка спора: детали заказа, переписка сторон, вложенные доказательства (фото товара при получении и т.д.), инструменты — «Вернуть средства покупателю», «Закрыть в пользу поставщика», «Запросить доп. информацию у сторон».

### 12.3 Управление каталогом категорий

Дерево категорий с возможностью добавления/переименования/слияния категорий, управление динамическими полями характеристик по категориям (см. 5.2).

### 12.4 Общая аналитика платформы

Дашборд с ключевыми метриками из PRD (раздел 11): число верифицированных поставщиков/покупателей, GMV, take rate, конверсия, NPS — с фильтрами по региону и периоду.

## 13. B2C-витрина (фаза 2)

### 13.1 Каталог для потребителя

Отличается от B2B-каталога упрощённым языком (без «опт»/«мелкий опт»), фото в интерьере/ландшафте, фильтрами по условиям содержания («солнце/полутень/тень», «для начинающих», «пет-френдли»).

### 13.2 Карточка растения для потребителя

Помимо стандартных данных — блок «Уход»: полив, свет, температура, пересадка — с иконографикой вместо текста, где возможно.

### 13.3 Корзина и профиль потребителя

Классическая e-commerce корзина (без мультивендорной сложности B2B — упрощена до одного чекаута), профиль с историей покупок и разделом «Мои растения» — трекер с напоминаниями об уходе (push/email), интеграция с AI-помощником для вопросов по уходу.

## 14. Адаптивность: mobile / tablet / desktop

### 14.1 Общие принципы

| Аспект | Desktop (≥1200px) | Tablet (768–1199px) | Mobile (<768px) |
|---|---|---|---|
| Навигация | Горизонтальное меню + боковая панель фильтров | Горизонтальное меню, фильтры — в выезжающей панели | Нижняя таб-панель (Каталог/Корзина/Заказы/Сообщения/AI) + гамбургер для второстепенного |
| Каталог | Сетка 4 колонки | Сетка 2–3 колонки | Список в 1 колонку с крупным фото |
| Карточка товара | Галерея слева, инфо справа, всё на одном экране | Галерея сверху на всю ширину, инфо снизу | Галерея-свайп, sticky-кнопка «В корзину» внизу (см. 7.3) |
| Формы (регистрация, добавление товара) | Многоколоночная раскладка, все шаги видны в прогресс-баре сверху | Одна колонка, прогресс-бар компактный | Один шаг на экран, кнопка «Далее» всегда видна внизу (sticky) |
| Таблицы (заказы, каталог поставщика) | Полная таблица со всеми колонками | Таблица со скрытыми второстепенными колонками (раскрываются по клику) | Карточный вид вместо таблицы — каждая строка становится карточкой |
| AI-помощник | Плавающее окно поверх контента (не блокирует страницу) | Плавающее окно, занимает до 40% экрана | Полноэкранный режим при открытии |
| Калькуляторы | Модальное окно или боковая панель | Модальное окно на весь экран | Полноэкранная последовательность шагов |

### 14.2 Специфика мобильной версии

- Приоритет на сценарии «в поле»: быстрое обновление остатков (5.2), сканирование QR-кода на партии товара для быстрого доступа к карточке (опционально, будущая фича).
- Оффлайн-режим для базовых действий у поставщика (просмотр каталога, черновик обновления остатков с последующей синхронизацией) — актуально для питомников с плохим покрытием сети на территории.
- Push-уведомления как основной канал для срочных событий (новый заказ, истекает время подтверждения).

### 14.3 Специфика планшетной версии

- Основной сценарий — использование администратором/менеджером склада на территории поставщика или менеджером закупок покупателя «на ходу» между встречами.
- Поддержка split-screen (например, каталог + корзина заявок одновременно) на iPad-подобных устройствах.

## 15. Ключевые пользовательские сценарии (flows)

### 15.1 Flow: Покупатель находит и заказывает товар (happy path)

Главная (вошёл) → Дашборд → Клик «Каталог» → Поиск «туя смарагд» → Применяет фильтры (регион, зона морозостойкости) → Открывает карточку товара → Использует калькулятор объёма (для изгороди 40м) → Результат добавлен в корзину → Переход в корзину → Видит группировку по поставщику, минимальный объём не достигнут → Добавляет ещё товар этого же поставщика → Оформляет заказ → Выбирает доставку и оплату (инвойс с отсрочкой) → Подтверждает → Экран успеха → Уведомление поставщику.

### 15.2 Flow: Поставщик обрабатывает новый заказ

Push-уведомление «Новый заказ» → Открывает приложение → Дашборд показывает виджет «1 новый заказ, подтвердить до 14:00» → Открывает заказ → Проверяет состав и остатки → Подтверждает срок отгрузки → Статус заказа меняется на «Подтверждён» → Покупатель получает уведомление → В день отгрузки поставщик меняет статус на «Отгружен» с указанием трек-номера → Автоматическое уведомление покупателю.

### 15.3 Flow: Новый поставщик проходит верификацию

Главная → «Регистрация» → Выбор роли «Поставщик» → Заполнение формы компании → Загрузка фитосертификата → Экран «На проверке» → (24–48ч) → Push/email «Ваш аккаунт подтверждён» → Онбординг-подсказка «Добавьте первый товар» → Пустое состояние каталога с кнопкой «Добавить товар» → Заполняет форму товара → Публикует → Товар появляется в публичном каталоге в течение нескольких минут (индексация).

### 15.4 Flow: Спор по заказу

Покупатель получает заказ, часть растений повреждена → В разделе «Заказы» нажимает «Сообщить о проблеме» → Загружает фото повреждённого товара → Заявка уходит и поставщику, и в очередь администратора → Стороны переписываются в разделе спора → Администратор принимает решение (частичный возврат) → Статус заказа обновляется, обе стороны получают уведомление с исходом.

## 16. Приложение: UI-кит и следующие шаги

### 16.1 Базовые компоненты, которые потребуются на этапе UI-дизайна

Кнопки (primary/secondary/destructive), поля ввода с состояниями (default/focus/error/disabled), чипы фильтров, карточка товара (3 размера: сетка/список/компакт для AI-ответов), статус-бейджи заказов, прогресс-степпер, таблица с сортировкой, модальные окна, тосты/снэкбары для подтверждений, скелетон-плейсхолдеры, компонент загрузки файлов с превью.

Переход к Этапу 3 — визуальный дизайн (UI Kit, дизайн-система, вайрфреймы/макеты ключевых экранов на основе этой карты) либо к детализации технической архитектуры, если она предшествует UI в вашем плане этапов.
